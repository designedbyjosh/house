# Visitor map and Umami Cloud

The homepage and `/visitors/` use locally bundled Natural Earth country outlines as a full-viewport wallpaper, focused on the current visitor's approximate country. The homepage keeps visitor metadata out of the content flow: a compact card above the country pin shows last access, saved visit count and current duration, with a link to full history and privacy controls. It opens by default only on spacious screens, opens from the pin on smaller screens, and hides before overlapping the journal. Unknown or unmapped countries omit this card. The `/visitors/` page retains the full history, privacy controls and a Show the world toggle. Optional aggregate activity comes from Umami Cloud. Static writing and navigation still work when either API is unavailable.

The optional aggregate map requires Pro API access (the account currently shows a $20/month upgrade with usage overages) and a server-only `UMAMI_API_KEY` Secret. No upgrade or trial was started. Without that optional connection the aggregate counters are hidden and the personal map remains fully usable. Use the account's API-key settings and scope the Vercel variable to Production. Do not put it in Git, browser storage, an issue, or a PR.

The current Cloud account rejected a second property with “Website limit reached.” No plan change or upgrade was made. Preview tracking is disabled unless a separate `UMAMI_PREVIEW_WEBSITE_ID` is deliberately supplied. Preview API access additionally requires its own `UMAMI_PREVIEW_API_KEY`; production credentials are never inherited. Do not point the preview variables at the production property.

`/api/visitor` returns only a validated Vercel country header and public tracker configuration, with `private, no-store`. Local development never trusts a caller-supplied geo header. No coordinates, IP, city, or API key are returned. `/api/visitor-activity` queries the fixed Cloud realtime endpoint with Bearer authentication and projects its response to totals and per-country counts. It never returns session IDs, event rows, referrers, visitor URLs or browser fingerprints. Data is cached for 30 seconds; failures return unavailable, never synthetic zeroes or stale activity. API credentials are not required to collect page views, but are required to display the global aggregates.

When the optional aggregate connection is enabled, its map activity describes the trailing 30-minute window, not an exact count of people online. Country focus uses network location; unknown locations keep a world view, and reduced motion disables the animated camera and marker pulse. One marker represents a country label point, not a visitor's physical location. Country counts depend on Umami's session estimation and can be affected by VPNs, blockers and shared devices. The local SVG omits Antarctica and may omit small territories at this scale. The text country label remains available independently of geometry.

## Personal history

`josh.visit-history.v1` stores at most 20 visits for 90 days in localStorage. Each visit stores a local-only ID, timestamps, visible-tab time, page-view count and up to 100 distinct paths. Paths exclude search and hash. Arriving directly or from another site starts a new visit, even within 30 minutes. Reloads, history navigation and same-origin links resume the recent visit identified by `josh.visit-session.v1` in sessionStorage. Because production uses `Referrer-Policy: no-referrer`, ordinary internal link clicks leave a single-use, path-matched navigation intent in tab storage for at most 10 seconds. It contains no query string and is never sent to the server. Thirty minutes without visible activity also starts a new visit. Existing v1 records migrate in place without resetting dates or durations.

Last here and Last stay use a snapshot taken before opening the page, so short returns immediately show saved activity. Reloads label the duration Time already spent to distinguish it from a separate stay. The journal displays the five most recent of up to 20 saved visits. Previously, all activity within 30 minutes was grouped together and the UI only showed the second record, making a quick return appear to have no history. Timer intervals are capped; tabs updating the same visit do not intentionally double-count an overlapping interval, and separate visits update their own records. Browser suspension, concurrent writes, storage clearing and clock changes make these approximate browser-local memories, not an authenticated cross-device history. Private/denied storage falls back to this page only.

DNT, GPC and a saved opt-out suppress both the tracker and local-history writes. The controls clear history or pause tracking. The Umami before-send hook strips query strings, fragments and referrer paths and rechecks the opt-out before each event. No local-history data, persistent custom visitor identifier, session replay or precise location is sent to Umami. Ordinary CDN/server request logging is separate from these browser controls.

## Delivery and verification

1. Run `npm run check`, `npm test`, `npm run build`, `npm run verify`, and `node scripts/security-check.mjs` using Node 24.
2. Preview with `PORT=4187 npm run dev`. Missing location and unavailable global activity are expected locally. Check desktop/mobile layout, privacy controls, navigation persistence and browser errors.
3. Review the PR and its Vercel preview. Production hosts retain the AWS static bridge; preview hosts serve the branch's static output. Both visitor API routes are handled by Vercel before the bridge.
4. Deliver through the existing PR/CI route. Only configure a production `UMAMI_API_KEY` Secret if optional API access has been separately authorized. The static release and Vercel functions must both deploy. CSP permits only the approved Umami Cloud script/collection hosts alongside same-origin resources.
5. Verify `/api/visitor` on `josh.engineer` has the expected public property ID and a no-store response. Visit a real page and verify the corresponding page view in the authenticated Cloud dashboard. With an authorized API connection, check `/api/visitor-activity` returns `connected` with a fresh observation and only allowed aggregate fields; on the free setup its unavailable state is expected. Test DNT/opt-out, reload, a new direct visit, internal navigation and backgrounding. Verify Last here, saved duration and the visible history rows survive the return. A ready preview is not proof of production collection.
